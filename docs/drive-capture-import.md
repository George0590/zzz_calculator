# 本机抓包导入驱动盘

实现日期：2026-10-19。计算器基于个人分支 `84a5267`；开发分支 `feat/drive-exporter-import`。
首版范围是国服正式 Windows PC；导出器固定于 `8efb171b5e6b33ec464e8b43a28e5fb792fbc160`，当前适配 `CNPRODWin3.2.0`。
Beta、国际服、云游戏及后续版本不在本次支持承诺内。

## 使用

1. 在本机启动新版计算器。打开“驱动盘 → 抓包导入”。准备好国服正式客户端，停在登录页。
2. 选择目标计算器账号。UID 可填写，也可留空；填写值始终标记为“声明 UID（未核验）”。
   与已有声明或 Enka 绑定不同时，会提示更换账号或明确确认调整声明，不改写 Enka 绑定。
3. 点“开始采集”，允许 Windows 对导出器的管理员授权。只有显示“已就绪，请登录游戏”时才点击游戏登录。
4. 若出现第二轮提示，保持同一游戏账号、同一版本和完全相同的库存，退出游戏，重新停在登录页，
   勾选确认并点“开始第二轮采集”；等再次显示“已就绪”再登录。
5. 完成后点“预览差异”。确认新增、更新、合并来源和疑似同盘，再点“确认入库”。
   显示“已导入本地库存”说明浏览器事务和回读已经完成；仅“采集完成”不代表已经入库。

每次任务固定目标账号，切换账号会阻止预览和入库；切回后需重新预览。目标账号删除后不能改投其他账号。
预览后库存有变更，提交会拒绝过期计划，结果仍可再次预览。
关闭面板会请求取消正在进行的采集；刷新后重新打开面板可恢复同一任务状态。
服务重启时未完成任务作废；成功文件保留以便恢复预览。授权窗口如未关闭，需要用户处理后才能新建采集。

## 库存与身份

- 使用现有原生 JSON v1 导入链、冲突组件、账号写入锁、冻结计划及回滚事务，不新建库存、不转换 OCR 数据。
- 游戏物品 ID 保持字符串，来源身份不包含任务 ID 或用户声明 UID；跳过 UID 后补填仍识别为同一张盘。
- 抓包入口固定 `removeMissing=false`。不删除缺失盘，不改变其他 JSON/Scanner 入口的选项。
- 同属性不同游戏物品 ID 分别保留；与旧 Scanner/手工/Enka 记录只有内容或形状相似时，必须人工确认。
- 更新保留原本地盘 ID、配装引用、角色专属、排除与多来源记录。`equippedBy=null` 表示未提供穿戴信息，保留已有穿戴。
- 游戏锁定独立更新，不等于计算器角色专属锁。未知版本、未知套装/属性、非法数值、重复 ID 阻止预览入库。

## 任务与接口边界

`backend/driveCapture.js` 管理独立 UUID 任务，`integrations/drive-exporter/launch.ps1` 仅提权 EXE。
Node、网页维持普通权限。本地接口只接受实际 loopback 连接、明确的 loopback Host、本机请求头和同源写请求，
生产模式关闭；没有任意命令执行或任意文件读取接口。

只有本任务明确 succeeded、正常进程结束、预期路径及原生 JSON/盘数校验全部成功，才显示 ready。
结果读入时再次校验内容哈希。退出码 0、文件存在、mtime 变化都不是单独的成功证据。
服务断开后 EXE 的 15 秒租约失效，终止自己的采集；程序不会调用全局 `pktmon stop`。
阶段、超时、第二轮控制与补丁细节见[导出器接入说明](../integrations/drive-exporter/README.md)。

## 回退

使用前建议从“驱动盘 → 批量导出”保存当前账号的原生备份。原始采集与日志仅在
`.local-runtime/drive-exporter/tasks/` 中，禁止提交或上传。

功能未发布、未推送，也未改动 `main`。代码回退应先将本分支修改提交或另存备份，再切回
`local/personal-calculator` 并重新构建；不要使用 `reset --hard` 或 `clean`。
导出器是独立运行目录，可停止任务后停用，不需要清理或迁移浏览器数据库。
代码回退不会撤销已经导入的浏览器库存；需要恢复库存时使用事先导出的备份和既有确认流程，核对删除范围后再操作。

AGPL-3.0-only 导出器与 MIT pktmon 的来源、许可和可重复构建方法见[接入说明](../integrations/drive-exporter/README.md)。
