# 本地可靠性、备份与计算方案

核对日期：2026-10-19。适用于本地开发分支；源码实现和隔离测试不代表日常服务已更新。
抓包导入见其[独立说明](drive-capture-import.md)，本次不调整抓包或扫描器协议。

## 任务与账号隔离

工作台开始优化前记录当前账号、角色和请求代号。切换账号、角色或离开工作台时，
终止旧 Worker 并结算等待中的请求；已经排队的成功、错误和预估消息必须检查任务身份。
仅当前任务的完整结果可自动选中方案。临时 Top 10、现有多核和最近一次完整请求缓存继续保留。

账号的新建、改名、切换、删除共用执行中状态。执行期间禁用重复操作，失败显示具体原因，
保留名称草稿或删除确认。旧的账号列表加载结果不能覆盖后发操作。

## 本地解析保护

库存 localStorage fallback、计算配置和优化设置读取区分“键不存在”和“JSON 解析失败”。
只有不存在时使用默认值；解析失败抛错、保留原字符串并阻止相关保存。
页面提供“导出原始内容”，启动失败时也可进入完整备份恢复。
该保护不意味着用户现有数据损坏，也不负责自动猜测、修补损坏内容。

## 仓库与选盘分页

驱动盘仓库每页显示 5 张盘；公共选盘组件及关闭使用限制界面时的旧选盘弹窗每页显示 10 张盘。
筛选在完整库存上进行，匹配结果变化回到第一页；显示匹配总量和当前页码。
分页仅截取渲染数组，优化候选和当前账号的批量导出不受页面、搜索或筛选限制。

仓库下方套装预设按代理人选择，一次只渲染该角色的全部预设。默认选择第一个有预设的角色，
返回仓库保留选择；所选角色已无预设时切到第一个有效选项。列表包含未知角色与公共预设，
保存后自动显示保存的角色。筛选依据预设的角色归属，不改变驱动盘专属、排除或穿戴关系。
卡片模式的预设编辑器也提供名称与角色输入，新增时默认使用列表当前选择的角色。

正式套装编号即使带 `scanner-set-` 前缀，只要已与目录一致，
就不应触发别名迁移和整份库存回写。读取完成后的账号过滤复用已规范化文档，
不再对全量盘重复规范化、计算指纹；持久化读取接口仍读取存储中的数据。
回归覆盖目录编号迁移幂等、连续读取不写回，以及后续写入和账号切换后的读取隔离。

仓库导航采用单页内存缓存（用户已确认的速度/内存取舍）：仅保留最近一个账号的仓库页，
其他页面仍按原生命周期卸载。离开仓库时卸载弹窗及其轮询，返回时保留列表和筛选控件。
槽位筛选改为无需动态测量的普通按钮，保留数量、键盘操作和窄屏局部滚动。

已有库存视图只在账号一致、没有错误或加载任务、视图未被替换，且本标签页未发生库存写入时复用。
写入尝试开始和结束都会使视图失效，包括事务失败；切换账号重新读取，旧加载回调不能覆盖新加载。
“刷新”始终强制读取。导入、编辑、锁定等操作保留现有事务和最新数据检查。
其他计算器标签页的改动不主动通知缓存：请点“刷新”或刷新整个页面。本标签页其他功能若主动加载了
最新库存，仓库会共享该结果。缓存不进入备份、不修改存储格式，也不减少优化候选或导出范围。
新增 `webapp/src/stores/inventory-cache.test.ts` 覆盖复用、写入失效、错误重试和账号/请求隔离。

## 完整个人备份

入口为“设置 → 完整个人备份”。格式为 `zzz-calculator-personal-backup`，版本为 `1`。
备份包含完整库存文档和本应用的浏览器设置原始字符串，覆盖：

- 全部账号、驱动盘、套装预设、来源、专属/排除、穿戴关系、绑定与事务历史。
- 各账号角色计算配置、音擎、队友、Buff、事件、敌人和选盘记录。
- 优化配置、命名计算方案、固定 A、扫描偏好和本地维护草稿。

不包含项目目录里的角色文件、游戏文件、扫描器安装文件；也不读取无关网站存储。
原“批量导出”仍只导出当前账号的全部盘。

第一版完整恢复采用整份替换，不混合合并账号。选择文件后预览当前和目标的账号数、盘数、
套装数、设置数及账号名称；先下载恢复前副本并勾选确认后才允许写入。预览后个人数据变化时拒绝应用。
恢复前应关闭其他计算器标签页，避免其他页面的内存状态继续保存。

恢复复用既有全局写入锁和库存记录，先把旧库存与原始设置写入 `personalDataRestore` 临时日志，
再写目标设置及最终库存。失败回滚，刷新启动时先恢复中断日志，再执行原驱动盘及 Enka 事务恢复。
不变更 IndexedDB 的数据库、object store 或版本。坏 fallback 只有在显式恢复、原始字符串仍一致时
才可替换，恢复前副本保留原坏字符串；此类恢复副本用于人工修复，不伪装成可直接回导的有效备份。

## 撤销普通导入

入口为“驱动盘 → 撤销上次导入”。只保留当前账号最近一次成功 JSON / 扫描导入的撤销记录，
使用既有导入事务的前后快照构造反向事务。预览和确认都检查数据是否变化。
相关盘被强化、删除，或当前账号配置、套装引用变化时拒绝撤销；无关的新盘可保留。
配置冲突检查按整个账号保守处理，因此某些与该次导入无关的配置编辑也会要求人工处理。
撤销成功后清除本次撤销记录，不提供多步历史回退。

失败回滚、中断恢复和 Enka 撤销保留原语义。抓包导入不生成普通导入撤销记录。
完整备份恢复与普通导入撤销是两个独立操作，完整恢复不会自动执行导入撤销。

## 命名计算方案与 A/B 对比

入口为工作台“计算方案”。每个账号、角色可保存多套名称不同的完整计算方案。
保存角色等级/影画/核心/技能、音擎、队友与 Buff、手动取消的默认 Buff、覆盖率等运行参数、
敌人、展开后的完整事件和实际参与计算的盘快照。应用时将事件作为自定义事件恢复，
避免后来修改管理员默认循环时替换原方案的事件。

新增独立键 `zzz-calculator.calculation-presets.v1`，按账号和角色隔离；不迁移现有配置。
原方案仍保留在其原有存储。此键自动纳入完整个人备份。

固定方案 A 后，与当前工作台 B 使用相同的当前计算公式重新计算，显示目标分数、关键面板、
音擎、队友/Buff、事件、敌人和每个槽位的盘及词条差异。目标类型不同时不计算分数差值。
A 使用保存时的盘与条件；它不是历史公式版本的伤害存档。

应用前按当前库存检查盘是否存在且计算属性一致；格式化单位、来源等元数据不同不算词条变化。
缺盘或词条变化会阻止应用，但 A 快照仍可查看。应用使用现有配置写入锁、冲突检查与失败回滚，
同时恢复套装触发参数，避免当前优化设置覆盖保存时的 Buff 条件。

## 验证入口与性能口径

- `webapp/src/stores/reliability.test.ts`：任务失效、防重复、坏 JSON 保留。
- `webapp/src/components/DriveDiscPickerModal.test.ts`：分页、全量搜索、跨页选择。
- `webapp/src/runtime/personal-backup.test.ts`：完整备份、过期预览、失败与中断恢复、坏 fallback。
- `webapp/src/runtime/drive-disc-import-transaction.test.ts`：普通撤销及既有事务回归。
- `webapp/src/runtime/calculation-presets.test.ts`、`webapp/src/stores/build.test.ts`：命名快照、原样应用与写失败保护。
- 相关账号、库存、存储兼容、Enka、浏览器 Worker 和雅优化器测试继续适用。

性能测量必须冻结同一份库存与计算输入，并保留目录对象之间的共享引用。
冷启动独立 Worker，关闭完整请求缓存，交错重复 1 / 2 / 4 个任务 Worker；分别记录端到端时间、
核心准备时间、首次临时结果和独立测试浏览器进程树的内存基线/峰值。
多核还包含一个控制 Worker；单核直接在控制 Worker 中搜索。
所有测量需比较完整 Top 10 的盘 ID、顺序及既有分数容差；单份库存结果不能外推到所有角色与条件。
